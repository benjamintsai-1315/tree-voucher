# CUBE Rewards 品牌排序需求（外部需求文件，2026-08-14）

> 來源：`CUBE Rewards品牌排序需求_v.0814.pdf`（需求方提供，本檔為文字轉錄，供內部審查與追蹤用）

## 需求目的

因品牌倍率或其它參數並非品牌顯示順序的唯一依據，實際營運需求可能發生以下情境：

1. **同一檔期內所有品牌倍率皆相同，但仍需指定品牌顯示順序**
   例如同一檔期內 A、B、C 品牌皆為 1.2 倍，但營運希望 A 品牌固定排在第一順位、B 品牌固定排在第二順位。
2. **不同品牌倍率不同，但低倍率品牌需優先顯示**
   例如 A 品牌為 1.1 倍、B 品牌為 1.2 倍，但營運指定 A 品牌需排在 B 品牌之前。
3. **同一檔期跨越不同月份時，同一品牌於不同月份可能有不同排序**
   例如 A 品牌於第 1 個月排序第 1、第 2 個月排序第 2。

因此，品牌顯示順序需由神坊提供可依檔期／生效期間設定品牌最終顯示順序的機制。

## 需求內容

神坊可設定各 Category 內各品牌於不同生效期間的 Rank，並由系統依排序規則產生最終顯示順序。

1. **品牌排序由神坊負責管理**
   - 品牌顯示順序由神坊設定及維護。
   - CR 不建立品牌排序 Mapping，亦不自行判斷品牌排序規則。

2. **品牌排序原則**
   - 品牌顯示順序以神坊設定之 Rank 為主要排序依據。
   - 品牌顯示順序不以倍率高低、品牌名稱筆劃大小或其他欄位作為主要排序依據。
   - 神坊可設定各 Category 內各品牌於不同生效期間的 Rank，並依排序規則產生最終顯示順序。
     例如：3 倍品牌可排序於 5 倍品牌之前。

3. **排序需支援不同生效期間**
   - 同一檔期內，不同生效期間可設定不同品牌 Rank。
   - 同一品牌於不同生效期間可有不同 Rank。

     例如：

     | 生效期間 | 品牌排序 |
     |---|---|
     | 第 1 個月 | A → B → C |
     | 第 2 個月 | B → A → C |
     | 第 3 個月 | C → A → B |

4. **排序值相同時之排序規則**
   - 當品牌排序值（Rank）相同時，以品牌倍率由大至小排序。
   - 若品牌倍率亦相同，則維持 API 回傳順序，不再由 CR 端重新排序。

5. **API Response 回傳之品牌順序即為 CR 最終顯示順序**
   - API 應依當下生效期間的排序設定，回傳已完成排序之品牌清單。
   - API Response 的品牌即為 CR 最終顯示順序。
   - CR 收到 API 後直接依回傳順序呈現，不再依倍率、品牌名稱或其他欄位重新排序。

## 內部初步討論記錄（PM Agent 記錄，非需求方文件內容）

與使用者討論後的初步技術方向（尚未定案，供 spec-review 參考）：

- 「生效期間」不另建獨立於 rotation 之外的區間實體；rotation 本身即為期間管理框架，Rank 設定應建立在 rotation 底下。
- 傾向以「預約生效時間點」（而非顯式 start/end 區間）的事件式模型記錄 rank 變更，取代維護生效期間的起訖區間；當下生效的 rank = 該 rotation 內，`effective_at <= now()` 中最新一筆記錄。
- 以上僅為技術方案雛形，rank 與 rotation 的綁定方式、事件粒度等仍有多處未定義，須經 spec-review 找出具體問題後，交需求方與內部確認。

## 初步比對現況（PM Agent 記錄，非需求方文件內容）

- 目前 `brands` 表僅有 `brand_category`（字串欄位），無獨立 Category 主表，也無任何 rank / sort_order 欄位。
- 目前 `get_current_rotation`（見 `docs/api/API Spec - get_current_rotation.md`）品牌排序邏輯為「依 category 分組 + 組內 name 字母序」，與本需求要求的 Rank-based 排序完全不同。
- 目前 rotation 為最小時間單位，無 rotation 內再切分「生效期間」子區間的既有機制。
- 目前系統無 brand 層級的單一「倍率」欄位；`discount_rate` 為 campaign 層級即時計算欄位，一品牌可能同時掛多個 active campaign。
- 相關既有問題：`docs/reviews/2026-07-06-spec-audit.md` AUD-013（排序 tie-breaker 與 collation 未定義）與本需求高度相關。
